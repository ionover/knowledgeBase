# HaspCode and Equals

## Для чего нужны ?

Быстрая или оптимальная работа с коллекциями.

## Самое важное 
- Если два объекта одинаковые - то хеш у них одинаковый
- Если два объекта разные - идеально что бы у них был всегда разный хеш. Но не обязательно.

- Если x.equals(y)  возвращает true, то hashCode() у обоих экземпляров объектов должны возвращать одинаковые значения.
- Но если x.hashCode() == y.hashCode(), то вовсе не обязательно, чтобы x.equals(y)  возвращало true, оно может возвращать как true, так и false

## Информация:
- В `Object` реализация `hashCode()` обычно связана с адресом объекта в памяти, но спецификация Java это жёстко не гарантирует.
- Коллекции и `Map` в Java переопределяют `hashCode()` и `equals()`, вычисляя результат на основе своих элементов.
- Массивы в Java не переопределяют `hashCode()` и `equals()`: по умолчанию сравнение идёт по ссылке (поведение `Object`).
- Для массивов стоит использовать методы из `java.util.Arrays`:
  - `hashCode()` и `deepHashCode()`
  - `equals()` и `deepEquals()`
- Методы с префиксом `deep` корректно обрабатывают вложенные массивы и сравнивают их содержимое, а не только ссылки.


## Камни
Использовать getClass() при реализации equals, а не instanceof. 
Причина в том, что согласно контракту метод equals симметричен. 
Если x.equals(y) == true, то y.equals(x) тоже должен быть true, а с instanceof это условие нарушается для дочерних классов.
