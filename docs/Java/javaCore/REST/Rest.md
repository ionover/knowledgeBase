#REST

## Для чего нужны ?

Representational State Transfer - архитектурный стиль взаимодействия компонентов распределённого приложения в сети.

## Самое важное

6 принципов:

1. Client-Server - чёткое разделение обязанностей
2. Stateless - каждый запрос должен содержать всю информацию чтобы его выполнить
3. Cacheability - ответы явно помечаются как кешированные или нет
4. Uniform Interface - API запросы с через стандартные HTTP методы, стандартные ответы с кодами и JSON/XML
5. Layered System - многоуровневая система строиться так, чтобы пользователь по сути ничего про неё не знал.
6. Code on Demand (опц.) - сервере может расширять клиент передавая ему JS

## Информация:

- Производительность
- Масштабируемость
- Гибкость к изменениям
- Отказоустойчивость
- Простота поддержки

Ни один из архитектурных принципов REST не говорит нам о том, какой транспорт мы должны использовать — HTTP или очереди.
Так же SOAP (Simple Object Access Protocol) это тоже протокол значит можно REST + SOAP такой же, как REST+HTTP.
Можно делать не только Rest-full, но и RestLike приложения.
