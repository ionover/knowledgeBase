# Generic

## Для чего нужны ?

Generic -> обобщенные типы. Пример List<T>.
Нужны, чтобы пользоваться полиморфизмом, при этом оставляя возможность пользоваться внутренними методами.
Type Inference

## Самое важное

Постоянно в коллекциях и стримах

## Информация:

Массивы в Java ковариантны. И это плохо String[] strings = new String[] {"a", "b", "c"};
Object[] arr = strings; теперь можно в arr вносить числа или POJO и в рантайме это убьёт программу.
«Дженерики» инвариантны и List<Integer> ints = Arrays.asList(1,2,3) List<Number> nums = ints; вызовет ошибку компиляции

### Wildcards (Integer extends Number)
? extends Number -> ставит левую границу (родители до Number).
? super Integer -> ставит правую границу (дети до Integer).
Если контейнер объявлен с wildcard ? extends, то можно только читать значения. В список нельзя ничего добавить, кроме null. Для того чтобы добавить объект в список нам нужен другой тип wildcard — ? super
можно сделать Collection<?> что равно <? extends Object>, а значит мы можем только читать.
Есть Raw(опустили тип) типы, но в современной java нет смысла в этом.

## Грабли

При компиляции типы стираются и везде получается УСЛОВНО Object (Type Erasure). Поэтому нельзя делать перегрузки методов например через
коллекции. Хотя стираются можно ограничить используя <? extends Object> и у различных объектов различное затирание например List в List а int в int
В процессе могут добавляться бридж-методы.
При стирании можно потерять часть информации о объекте, объекты которые не теряют иноформацию (например примитивы) это Reifiable типы.
Exception не могут быть парметризированными (написано однажды работает всегда - больно бьёт) Throwable и его подтипы не могут быть параметризованы потому что try-catch првоеряет типы.
Heap Pollution - загрязнение кучи.


## Дополнения

Можно использовать instanceof бегая по коллекции, чтобы определять классы объектов.
Можно сделать List<Parent> и add.(new Child), но наоборот нельзя (полиморфизм работает).
