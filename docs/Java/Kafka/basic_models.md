# Вопрос

- Основы модели данных.
- Что такое topic, partition, offset в Kafka?
- Зачем нужно партиционирование и как оно влияет на порядок сообщений и масштабируемость?

# Ответ

Kafka — это кластер, состоящий из нескольких брокеров (экземпляров приложения Kafka).

**Топик (Topic)** — некоторый логический контейнер, где лежат сообщения (в 1 брокере может быть несколько топиков).

**Партиция (partition)** — набор независимых очередей внутри топика. Каждая партиция — это append-only-лог сообщений.

Если нужно соблюдать FIFO, то нужно закидывать такие сообщения в 1 партицию. Для этого используется роутинг по ключу. Если ключа нет, то Kafka положит сообщение в случайную партицию (либо каждый раз в следующую, либо батчами). Если у сообщения есть ключ, то от него ищется хэш, и по этому хэшу сообщение попадает в нужную партицию.

Kafka гарантирует, что каждая партиция топика будет обрабатываться только одним консьюмером в группе.

**Offset** в данном случае — это порядковый номер сообщения в партиции (указатель: консьюмер знает, к какой цифре в указателе обратиться, и её можно двигать, за счёт чего можно всегда держать «последнее» или перечитывать очередь).

Для скорости работы топик не гарантирует порядка: он ставит сообщения в партиции, а из этих партиций уже читают сервисы с разной скоростью в зависимости от своей нагрузки. Также, если консьюмер какой-то партиции вышел из строя, то проводится ребаланс, и сообщения в итоге всё равно могут быть обработаны. Можно сделать топик размером в 1 партицию, но это подходит только для очень узкого типа задач.

По сути, верхняя граница партиций — это верхняя граница параллелизма работы.
