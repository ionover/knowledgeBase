# Consumer и consumer group

## Вопрос

Что такое consumer group, как происходит распределение партиций между consumer'ами (rebalancing), что будет, если
consumer'ов в группе больше, чем партиций?

## Ответ

Consumer (консьюмер) — читатель из очереди сообщений. Консьюмеров можно объединить в группу для улучшения скорости и
многопоточности. По сути, мы подразумеваем, что у нас может быть не одно приложение-читатель, а кластер таких
приложений.

Поскольку Kafka — это просто пайп сообщений, то ей всё равно, кто её читает: её задача — принять сообщения и дать их
считать.

Как правило, за конкретной партицией закрепляется конкретный консьюмер из группы. Если у нас количество партиций равно
количеству консьюмеров, то каждый консьюмер просто читает свою партицию.

Если добавляется новый либо умирает старый консьюмер, Kafka производит ребалансировку. Если один исчез, то партиция,
которая осталась без консьюмера, будет назначена другому консьюмеру, и очередь всё равно продолжит читаться.

- **Если consumer'ов больше, чем партиций:** лишние consumer'ы вообще не получают партиций и простаивают (idle) —
  партиция может быть закреплена только за одним consumer'ом в группе, поделить её на двоих нельзя.

- **Если партиций больше, чем consumer'ов:** некоторые consumer'ы читают несколько партиций.

Группа consumer'ов совместно потребляет топик. При этом Kafka гарантирует, что каждая партиция обрабатывается ровно
одним consumer'ом в группе в любой момент времени.

Если нужно, чтобы одно и то же сообщение обработали независимо несколько раз (разными «потребителями» по смыслу), их
сажают в разные consumer group.

Есть разные алгоритмы ребаланса: например, `StickyAssignor` делает `stop-the-world`, а `CooperativeStickyAssignor`
снижает паузу. Есть проблема `rebalance storm`.
