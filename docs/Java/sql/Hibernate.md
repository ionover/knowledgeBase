Обращение к БД.

## Информация

### Каскады

Что происходит с зависимыми объектами при изменении главного. Например, можно `OneToOne(cascade = CascadeType.ALL)`, но ещё есть:

- `ALL` — применяются все каскадные операции: при `rep.save(new Person(new Card()))` сохранятся оба объекта, а при удалении `Person` удалятся и его связанные `Card` (если каскад задан на этой связи).
- `PERSIST` — при сохранении главного объекта автоматически сохраняются и связанные с ним новые объекты.
- `MERGE` — при `merge` главного объекта изменения также переносятся в связанные объекты.
- `REMOVE` — при удалении главного объекта удаляются и связанные с ним объекты.
- `REFRESH` — при обновлении состояния главного объекта из БД обновляются и связанные объекты.
- `DETACH` — при отсоединении главного объекта от контекста персистентности отсоединяются и связанные объекты.
- `REPLICATE` — при репликации главного объекта в другую БД реплицируются и связанные объекты.
- `SAVE_UPDATE` — при `save` или `update` главного объекта те же операции каскадно применяются к связанным объектам.
- `LOCK` — при наложении блокировки на главный объект блокировка каскадно применяется и к связанным объектам.

### N+1

Пути решения проблемы:

- `LAZY (EAGER)` — само по себе не убирает проблему: `LAZY` чаще откладывает `N+1` до момента обращения к связям.
- `Query + fetch` — обычно нужен отдельный запрос в `JpaRepository` (например, с `JOIN FETCH`), чтобы подтянуть связи сразу.
- `Графы зависимостей (EntityGraph)` — можно использовать именованные и динамические графы, вызывать через `EntityManager` или аннотации; у одного класса может быть несколько графов по имени.
- `Батчи` — можно задать в приложении или над методами репозитория, и тогда это уже не `N+1`, а примерно `1 + N/размер батча`.
